## 让内容拥有自己的位置

个人网站可以是一份名片，也可以成为持续记录的地方。一个简单的起点是区分三种内容：Projects 回答正在关注什么，Blog 表达经过整理的观点，Notes 收集暂时还没有形成完整文章的发现。分类不是为了给每个想法增加门槛，而是让读者知道自己正在读什么。

| 内容     | 适合放什么                   | 更新方式       |
| -------- | ---------------------------- | -------------- |
| Projects | 项目背景、范围与下一步       | 随进展修订     |
| Blog     | 一次实践的分析或技术文章     | 发布后补充说明 |
| Notes    | 一个问题、一段观察或学习线索 | 少量、频繁更新 |

### 先写，再整理

笔记可以很短。记录“为什么这个问题值得继续看”，比堆放一串链接更有帮助。等到几个笔记围绕同一个问题形成联系，再整理成文章。文章不必追求一次说尽，把当前的理解与尚未确定的部分分开，反而更容易继续生长。

## 把维护成本控制在文件里

Markdown 让内容和界面保持相对独立。一篇普通文章只需要一个文件与一小段元数据：

```yaml
title: '一篇新的开发记录'
description: '用一句话说明读者会看到什么'
date: 2026-10-10
tags: ['开发手记']
draft: true
demo: false
```

草稿可以先留在仓库里，确认标题、链接与正文之后再公开。需要提示块时再使用 MDX，普通文字则继续使用 Markdown。这种选择让编辑过程贴近写作，也减少了每次发布时需要处理的工具。

## 让页面安静一点

留白、稳定的行距和清楚的标题层级能够帮助阅读。色彩用于提示链接、类别和当前页面；代码与技术标签使用等宽字体。首页只展示最近的少量内容，把完整目录交给各自的列表页。手机上应能顺畅地读完一篇文章，代码块和表格则在自己的容器内横向滚动。

网站的特色不需要从复杂交互开始。持续留下真实的内容，慢慢形成自己的语气，往往比一次加入许多功能更能让这个地方变得有辨识度。
